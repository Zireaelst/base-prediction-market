# Decisions
- 2026-10-29: Single Next.js TypeScript application with persistent local SQLite and server-side random, hashed sessions; no separate worker/service for MVP. Public venue reads cached with observed timestamps. Research repository stays separate at `b1167defe82afd37f1eeda31d6e8b1350c462943`; Limitless SDK reference `f57d55951ad6c9740387b26b6629ffb03d55fd44` (v1.3.0). An initially empty app repository had no commit from which to create isolated worktrees; workers owned nonoverlapping files.
- The AXON attachment was not present in the accessible workspace. Written brief governs: original black/off-white/lavender, bundled Geist Pixel Square for display, Geist Sans/Mono for UI/metadata, adaptive ASCII/dither. No claim of AXON visual fidelity. Font package `geist@1.8.2` is SIL OFL 1.1 licensed.
- [Official Limitless docs](https://docs.limitless.exchange/developers/introduction.md) describe Base mainnet-only and no sandbox. Application performs only public reads; paper positions are local simulations, not venue fills. Initial MVP needed no wallet, contract or deployment; the later optional wallet-sign-in feature uses **off-chain Base Sepolia EIP-4361** signatures only. No application chain writes or contracts. Base Sepolia 84532 remains the only authorized chain for wallet signing and any future authorized writes.
- `midpoint-v1`: one current open-market Limitless CLOB snapshot midpoint used as hypothetical price; whole-dollar paper stake, synthetic immediate fill, zero fees/slippage, synthetic shares = stake/price. Current live read is required server-side; settlement follows venue payout numerators, with revision history. No AMM estimate, executable quote, wallet funds or venue order. Initially ambiguous/contradictory winner/payout leaves results pending; later ambiguity marks any previous settlement/score **last confirmed** without erasing history until a decisive observation returns. Split outcomes have no binary forecast score.
- Free forecasts record YES probability even when the stated pick is NO. Revisions lock at deadline, early venue closure, terms change, stale/outage or resolution. Brier-derived scoring reconciles only confirmed binary venue resolution; corrections append immutable score history.
- In-app notices are opt-in and local; no push, email or background settlement worker. Foreground activity reads perform bounded, concurrent rotating reconciliation so local history remains usable during venue outage. Visible venue screens refresh every 30 seconds, mark observations older than two minutes stale, and block stale paper confirmation. Catalog pagination accumulates venue pages with slug deduplication; raw-page continuation survives filtered records and first-page generation changes discard old pages. Loaded-only search is labeled.
- 2026-10-30 wallet-auth cutover: optional injected EIP-1193 wallet sign-in alongside unchanged password accounts; EIP-6963 discovery with explicit choice when multiple providers announce and legacy `window.ethereum` fallback. No hosted wallet SDK or new contract. Client checks/requests Base Sepolia before `personal_sign`; server stores exact five-minute SIWE challenge plus hashed nonce in SQLite, checks address/origin/chain/time, verifies EOA locally through `viem@2.57.13`, and verifies contract wallets only via a chain-checked read-only Sepolia RPC. Consumption, account creation and one-hour session issuance share a SQLite transaction. No linking to password accounts; wallet handles have reserved namespace and legacy collision fallback. Smart-account session revocation is bounded to one hour, not instant. Public profile omits wallet address.
- Independent wallet review identified preemptive password-handle squatting and too-narrow smart-signature length validation. Reserved the namespace, added legacy collision recovery, allowed bounded variable-length hex contract signatures, and added a failing-before/passing-after collision regression. The harness lists preferred `openai-codex/gpt-5.6-terra` and `openai-codex/gpt-5.6-sol`, but `task` rejected model overrides except for `seance`; workers ran under harness default, not a claimed preferred override. Browser-tested wallet provider was simulated; real extension and ERC-1271/6492 accounts remain unverified.
